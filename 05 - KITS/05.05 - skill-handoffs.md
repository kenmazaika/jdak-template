# Kit · Skill pipelines & handoffs

**What it is:** the pattern for chaining skills into a **multi-phase pipeline** — a linked list of
skills that each do one phase, hand the work to the next, and keep a record of where it is. One skill
is one move; a **pipeline** runs moves in sequence.

## The core move: the file IS the baton

A phase ends by **writing its output to a file**, then the next phase **starts a fresh process** that
reads that file. The new process gets the *artifact*, not the reasons behind it — so it can critique,
take a different angle, or catch what the previous phase rationalised away.

- Don't chain everything in one long context — it gets polluted with "this is a good idea".
- Write the baton when there's a *point* to it (a handoff to a different frame), not excessively.
- The pipeline accumulates: each phase's file is a step in `runs/<date>/`.

> File-baton > Kanban. Both work; a file needs no board and syncs everywhere.

## The shape

```
<ball-or-loop>/
├── runs/<date>/
│   ├── 01-phase.md      # phase 1 output (the baton)
│   ├── 02-phase.md      # phase 2 reads 01 → writes 02
│   ├── 03-phase.md      # ...
│   └── 04-verdict.md    # the gate
```

Numbering = order. Each file is self-contained: it carries everything the next phase needs, so the
handoff survives a fresh process (or a new session, or another agent).

## End-of-skill handoff signal

A skill that is *part of a pipeline* should end by emitting a **"ready for the next skill"** handoff
to a known place — not a chat message. That's the link in the linked list.

## Worked examples in this stack

- **`blog-post-pipeline`** (the "Jake process") — chains `draft-forge` → refinement passes →
  `seo-retrofit` → per-platform retrofits → images → Proof docs → staged drafts → the distribution
  packet. Each phase leaves artifacts the next consumes.
- **`06 - LOOPS`** — a loop's `runs/<date>/` is a baton chain (`01-scan → 02-candidate → handoff →
  03-critique → 04-verdict`); the loop hands off to a **fresh process** for the skeptical read.
- **`media-company`** — signal-scout → researcher → content-strategist → long-form-writer →
  distribution-bot → editor, strictly sequential, with campaign state files as the batons.
- **QBall handoffs** (`05.04 - qball.md`) — the same pattern at the job level: `HANDOFF-<date>.md` +
  a resume key.

## Rules

- **One phase, one file.** If a phase produced nothing worth carrying, it produced nothing.
- **Fresh process for critique.** Autonomy comes from *not* sharing the author's context.
- **Idempotent resumes.** A phase should be re-runnable from its baton (the resume default).
- Anything written into the vault follows the **Vault Voice Guide**.
