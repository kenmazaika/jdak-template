# Kit — Inbox-message playbook

**How the agent writes an agent → owner inbox message** so the owner can decide in **one skim**. This
is the doctrine the **`send it to inbox`** macro follows.

## The job

**One screen, one decision.** The note answers *"what do I need to do?"* — nothing else. Depth lives in
the **linked artifact**, not the note.

## Anatomy (top → bottom)

1. **Summary** — one line: the gist **and** the ask. So the owner never opens the artifact cold.
2. **Source** — an **Obsidian link** `[[path|label]]` → click straight into the real file.
3. **Detail** — 3–5 bullets: **only** what's needed to decide.
4. **Your action** — markdown **checkboxes**, one outcome per box. The box set is chosen **case by case** (see below).
5. **Comments** — where the owner types a reason / notes.
6. **Suggested actions (best takeaways)** — **at the bottom**: the agent's case-by-case recommendation of the *best* next moves, one line each.

> The **checked box is the owner's approval** — the inbox sweep performs it. No second ask.

## Feedback

If a note is feedback (the owner says **"this is feedback"**, or gives a reason on a box), the sweep
appends it **verbatim** to the ONE corpus `05 - KITS/05.05 - feedback/feedback.md`, tagged with its target
+ a link. It never becomes a rule directly — the weekly mining loop (`06 - LOOPS/06.06 - feedback-mining`)
bches the corpus and proposes the top ≤3 changes. Kit: `05 - KITS/05.05 - feedback/README.md`.

## The case-by-case step (the important one)

Before writing the boxes, the agent asks: **"What are the few things the owner could do here — and which
are best?"** That answer *is* the action set. Do **not** reuse a fixed set; derive it per item.

- A publish draft → *Accept & publish · Reject · Reject + reason*.
- A research question → *Research it · Park · Kill*.
- A channel proposal → *Adopt · Park · Skip*.
- **Anything long-running** → add *📋 Create a ticket* (and *🗂 Create a card + ticket* when it's a tracked outcome you'll carry to done).
- **A handoff that becomes real work** → add *📋 Convert to ticket* — the note moves + rewrites into `00.03 - tickets/` and runs there (the handoff leaves the inbox).

Then put the **single best** one first (or mark it), and list the **takeaways** at the bottom so the
owner sees the agent's reasoning at a glance.

## Hard rules

- **Frontmatter:** `loop:` · `item:` · `action: pending` · `obsidian:` (the link).
- **File:** `00 - INBOX/00.01 - handoffs/YYYY-MM-DD-<topic>.md` (from the `handoff` template).
- **Mirror** one line on the root `INBOX.md` board; link the note into today's **daily note**.
- **Voice guide:** short · skimmable · ≤20-word sentences · bold the key term · no fluff.

## Anti-patterns

- ❌ Walls of prose. ❌ Restating the artifact in the note. ❌ Vague asks ("look at this").
- ❌ No checkboxes. ❌ A generic action set that ignores what *this* item actually needs.
- ❌ Burying the ask — the summary must carry it.
