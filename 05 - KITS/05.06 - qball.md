# Kit · QBall — the resumable work bundle

**What it is:** a **QBall** is a self-contained bundle of partially-done work — the state, the receipts,
the lineage, and the *why* — in one stable folder, so it can be picked up cold and continued later by a
human or an agent **without losing context**.

**The name:** borrowed from the physics *Q-ball* — a stable, non-dissipating packet of energy. Same idea:
a packet of work that holds itself together and doesn't leak context across sessions.

**The one-line definition:**
> A throwable, resumable intermediate asset — a folder capturing *what a piece of work is, where it
> stands, what already ran, and why it's done this way*, so the next person (or agent) can pick it up
> with no briefing.

## Where QBalls live

- **Ball root:** `01 - PROJECTS/` — each ball is a folder (`01.NN - <slug>/`).
- Registered in `BALLS.md` (workspace registry) — one line per ball, by recency + status.
- Same shape whether the work is running in the agent or handed to a human.

## The six layers

| Layer        | File(s)                   | Holds                                                                                                     |
| ------------ | ------------------------- | --------------------------------------------------------------------------------------------------------- |
| **state**    | `BALL.md`                 | frontmatter (`status`, `next_action`, `last_thrown`) + a one-screen read + open decisions + how to resume |
| **why**      | `decisions.md`            | the reasoning — rejected framings, judgment calls. **Read this FIRST**                                    |
| **lineage**  | `LINEAGE.md`              | the exact prompts / models / providers / commands behind each version                                     |
| **receipts** | `receipts/`               | proof of what actually ran (verifier / critic / proof docs)                                               |
| **inputs**   | `prompts/`, `dictations/` | the exact briefs + source dictations                                                                      |
| **log**      | `commands.log`            | append-only record of every invocation                                                                    |

## The two rules that make it work

1. **Never lose the source.** A ball **symlinks** assets — never copies. Copying forks the source of
   truth and the ball drifts.
2. **Log every change in all four files.** Touch the work → update `LINEAGE.md`, `commands.log`,
   `decisions.md`, and `BALL.md` — not just the artifact.

## Handoff & resume

- **Handoff = writing the state into the ball.** Pause mid-flight → write `HANDOFF-<date>.md` (phase
  reached · artifact paths · open decisions · the **exact next action**), mint a **6-digit resume key**,
  log it. Nothing important stays only in chat.
- **Resume order:** `decisions.md` (why) → `BALL.md` (state + open decisions) → latest `HANDOFF-*.md`
  → `LINEAGE.md`. **Default action = re-run the last unfinished step.** Open with a state card:
  *"Where we are: <phase>. To push to <next phase>: <what I need>."*

## The ship-it signal

A ball that is **draft-complete + verified but not published** is the highest-value state — the most
likely next action. Surface it first.
